1 개요 Overview

배경 — AI가 코드를 생성하는 개발 환경에서, 요건 정의부터 PR 생성까지의 전 흐름을 자동으로 검토·감사하는 툴이 필요하다.

  • 요건 → AI 코드 생성 → 검토 → 머지 → PR 생성까지의 파이프라인을 자동화
  • 각 단계를 독립적인 서브에이전트로 운영하여 효율적인 실행과 검토를 실현
  • 요건 변경에 유연하게 대응하는 구조 확보
실행환경: Claude Code 오케스트레이터 + 서브에이전트 MD 파일 기반 룰 관리
00 변경 관리 (Change Management) 상시 참조

요건 변경 발생 시 항상 참조하는 공통 룰. 변경 규모에 따라 재시작 지점을 결정한다.

변경 규모재시작 지점
소규모 (일부 스펙 수정)05 태스크 실행
중규모 (기능 추가·삭제)03 태스크 분해
대규모 (요건 근본 변경)01 요건 정의
01 요건 정의 (Requirements Define)
  • 사람이 직접 작성하거나, AI에게 초안 작성을 의뢰
  • AI 초안의 경우 사람의 승인이 필요
  • 각 요건에 고유 ID (REQ-XX) 부여
  • 기능 요건 / 비기능 요건으로 분류
02 요건 리뷰 (Requirements Review)
  • 모호성·누락·일관성·실현 가능성·테스트 가능성 검토
  • 각 요건에 상태 부여
  • 전체 ✅ 판정 시에만 다음 단계로 진행
✅ 통과 ⚠️ 주의 ❌ 실패 → 01 피드백
03 태스크 분해 (Task Decomposition)
  • AI가 MD 지시사항 기반으로 요건을 태스크로 분해
  • 1 태스크 = 1 PR 단위의 작은 구현 단위
  • 각 태스크에 ID (TASK-XX), 의존 관계, 병렬 가능 여부 명시
  • 모든 요건이 최소 하나의 태스크와 연결되어야 함
04 태스크 분해 검토 (Task Decomposition Review)
  • 분해 결과가 요건을 올바르게 커버하는지 검토
  • 의존 관계의 순환 여부 확인
  • 지나치게 큰 태스크(L 사이즈)는 재분해 요청
❌ 실패 → 03 피드백
05 태스크 실행 (Task Execution) 병렬 가능
  • 각 태스크를 독립 서브에이전트로 실행
  • 의존 관계가 없는 태스크는 병렬 실행
  • 코드 생성 기반: 해당 태스크의 요건 + 팀 컨벤션
06 태스크 코드 리뷰 (Task Code Review)
  • 요건 충족도 (요건 ↔ 코드 매핑)
  • 코드 품질 (보안, 예외 처리, 가독성)
  • 요건 외 임의 구현 감지
  • 실패 시 해당 태스크만 05로 재실행
❌ 실패 → 05 재실행
07 태스크 머지 (Merge)
  • 검토 통과된 태스크를 머지
  • 의존 관계에 따른 머지 순서 준수
  • 커밋 컨벤션 적용 / 충돌 감지 및 처리
<type>(<scope>): <subject> [TASK-XX] 타입: feat / fix / refactor / test / docs / chore 예시: feat(auth): 로그인 토큰 검증 추가 [TASK-03]
08 통합 검토 (Integration Review)
  • 모든 태스크 머지 완료 후 전체를 하나로 보는 최종 검토
  • 태스크 간 충돌 및 누락 확인
  • 전체 요건 커버리지 최종 확인
09 PR 생성 (PR Generation)
  • 연관 요건과 태스크를 연결한 PR 설명 자동 생성
  • PR 간 관계 명시 (선행 PR / 후속 PR)
  • 트레이드오프는 팀 기준에 맞게 커스텀 작성
## 개요 ## 연관 요건 (REQ-XX) ## 이 PR의 역할 (PR 간 관계) ## 구현 내용 ## 트레이드오프 ## 테스트 방법
