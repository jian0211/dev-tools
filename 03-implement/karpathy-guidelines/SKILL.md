# karpathy-guidelines

実装や既存コードの修正を頼まれたとき、先に考えてから頼まれた行だけ直す。

小さな誤字修正や、一箇所の明らかな直しには使わない。慎重さが速度を落とすだけだからだ。

## いつ

- コードを書くとき
- 既存のコードを修正するとき
- レビューやリファクタで、どこまで触るかを決めるとき

## 手順

1. 仮定を先に言う。複数の解釈があるなら、黙って選ばず両方出す。不明な点があれば、その名前を言って止める。
2. より単純な方法があればそれを言う。頼まれていない機能、一回しか使わない抽象化、頼まれていない設定は入れない。
3. 成功条件を検証できる形にする。例えば「バリデーションを足す」は「不正な入力のテストを書き、それを通す」にする。複数手順なら、各手順の確認方法も書く。
4. 頼まれた行だけ直す。隣のコメント、整形、壊れていないコードは触らない。自分の変更で使われなくなった import や関数だけ消す。もともとあった不要コードは、頼まれない限り消さず一言だけ伝える。
5. 成功条件で確認する。条件が「動くようにする」だけなら、確認できる条件に直してから進む。

## 終わったら

変えた行が依頼に直接たどれる。仮定と成功条件が残っている。依頼と無関係な差分がない。
